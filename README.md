# 保义改写 Agent · 宿主版 0.3

安装一次后，直接在 Codex、Claude Code、WorkBuddy 等应用里发文章就能改写。它使用应用本身的模型，不需要另配 API Key、启动网页或运行常驻服务，仍会使用宿主账号的额度和工具权限。

这个 Agent 通过 Skill 安装。随包的程序保存状态和反馈，执行检查与评测，并控制版本启用；文章生成和语义审校交给当前应用的模型。

## 最快开始

从 [v0.3.0 发布页](https://github.com/Mingqi-111/faithful-writing-agent/releases/tag/v0.3.0) 下载附件 **faithful-writing-agent.zip**。包里只有一个同名技能目录，可从支持 ZIP 的技能入口导入。源码下载包供查看和开发使用；用安装脚本安装时，即使源码目录带有 `-main`，目标技能名也固定为 `faithful-writing-agent`。

把这个包交给 Codex 或 Claude Code，发：

> 请把 faithful-writing-agent 安装到当前写作项目。以后我发文章时，用它保留原意地改写，反馈和偏好保存在这个项目中，不配置独立 API，也不启动网页。

应用可以执行包内的项目安装脚本。手动安装时，把整个技能文件夹放到对应位置：

| 应用 | 安装位置 / 入口 | 本版状态 |
|---|---|---|
| Codex | 项目 `.agents/skills/faithful-writing-agent/` | 本地状态机可运行；提供本次验证记录 |
| Claude Code | 项目 `.claude/skills/faithful-writing-agent/` | 按官方接口适配，未在 Claude 实机验收 |
| WorkBuddy | 技能 → 添加技能 → 上传技能；或项目 `.codebuddy/skills/` | 官方支持入口，未在 WorkBuddy 实机验收 |
| Claude 普通聊天 | Customize → Skills → 上传 ZIP，并启用代码执行 | 会话内可执行；精确记忆跨会话需导出/恢复 |
| 扣子 / Coze | 桌面端添加本地技能目录；或上传技能后由平台打包部署 | 已核实官方入口，需验证代码环境和状态保存 |

各平台的入口和官方来源见 [平台接入说明](references/platforms.md)。一个 ZIP 不会自动获得所有应用的权限，也不保证各平台的长期记忆完全相同。桌面或编程环境通常更适合这个需要保存状态的版本。

安装后，直接发文章和要求即可：

> 改写这篇抖音科技口播，意思不要变：……

不指定场景，就保留原文文体；已经自然的文本可以不改。首次使用不需要提供历史作品。现有五类预设：通用文章、抖音科技、小红书、客服与演讲稿。

## 按需去模板化

普通“改写/润色”沿用 0.2 的编辑范围。想减少套路表达，可以说：

> 去 AI 味，保留原意和我的口语，不要改论述结构：……

这会启用 light，精简重复程度词、空泛互动和预告。脚本会对照原文与改稿，检查是否新增冒号总分、对称句、衔接词或假揭示，特色口语被替换时也会提醒审校。

> 去 AI 味，可以调整语气和论述结构，但事实和独立观点不要变：……

这会启用 strong，进一步整理结构，拆掉没有独立信息的假揭示。真实排除项、因果判断和事实范围仍须保留，不会把“所有人”静默改成“很多人”。词表提示都是供编辑复核的 warning，不能判断作者身份，也不要求全部清零。

新增的 intensity、rhetoric、address 偏好仍须经过原有验证。它们只在本次已开启的模式内生效，不会因为以前接受过强改就自动开启 strong。用户默认收到完整终稿，参数和审校表由应用处理。

## 反馈也用自然语言

> 这版采用了。

> 我最终改成下面这样，请记录这次修改：……

> 根据已经记录的反馈，评测是否可以改进我的科技口播偏好。

> 启用通过验证的候选。／回退到上一版。

应用会在后台调用本地脚本，用户不用填写 JSON 或输入内部命令。只有明确反馈才算证据；保存、复制或没有回复，都不自动表示喜欢。

同一用户在同一场景积累至少 6 篇不同原文的采用反馈后，较早的记录用于提取偏好，最后 3 篇留作比较。每条候选偏好至少需要 3 条训练证据，通过固定用例和保留稿检查后才能启用。全平局不算改进，风格评分也不能抵消内容错误。

如果应用没有独立审校能力，就记录为自审。这不等于独立 benchmark，也不能默认自动升级。工具无法只凭 JSON 证明审稿人独立，因此会保留执行方式和记录供复核。用户可以明确选择降低验证门槛，应用不能代替用户作这个决定。

## 运行 Benchmark

直接说“运行离线检查”或“用当前应用跑 3 个真实 benchmark 用例”，应用即可执行。现有 40 条确定性规则样本和 34 条公开改写开发用例，覆盖误改、内容保留、表达改善，以及 off/light/strong 对照。新增场景采用原创合成材料。

本次还整理了 100 篇具名媒体文章，从 85 篇发布者标注为 AI 生成的中文文章中选出 50 篇问题样本和 7 篇自然对照。这些材料用于完善信息重复、空转场、有效列表、直接引语和真实立场的判断。来源数量、实际审查范围、取样偏差和规则映射见 [语料研究](RESEARCH.md)。完整媒体正文不随技能包分发，日常改稿也无需加载研究语料。

每篇先保存改稿，再做语义审评。脚本把数字、链接、代码、引语等差异与实际审校结果合并，最多允许三份候选，未通过就回退原文。

通用 benchmark 要求每条生成任务完成，缺记录不能算通过。个性化 benchmark 则比较旧策略和候选策略，保存成对的输出与审评。生成和判断都使用当前应用的模型，不调用外部模型 API；自审与另一个上下文的审查会分开记录。具体流程见 [评测协议](references/benchmark.md)。

小样本和模型审评不能证明长期收益。模型不会为了提高通过率自行修改规则；发现新的失败模式，应先整理成待审阅案例，再更新公开开发集。

## 文件和数据

```text
faithful-writing-agent/
├── SKILL.md                 宿主入口与行为流程
├── agents/openai.yaml       Codex 展示和触发配置
├── scripts/agent.py         无网络的状态机命令
├── scripts/runtime/         检查、记录与评测门槛
├── scripts/install.py       可选的项目安装器
├── references/              编辑、场景、审校、优化与平台协议
├── benchmarks/              固定检查器样本与真实改写用例
├── tests/                   程序行为测试
├── evidence/                公开执行记录与语料研究元数据
└── licenses/                上游归因与许可
```

Python 3.11+ 标准库即可运行，不需要额外的 pip 依赖。优先使用应用自带的代码环境，用户无需启动网页服务。如果应用完全没有代码或文件能力，就只能提供基础改稿和自审，不能声称已运行完整 benchmark 或长期反馈流程。

状态保存在**写作工作目录**的 `.faithful-writing-agent/`，与技能安装目录分开，重新安装不会自动覆盖。持续写同一系列内容时，使用同一项目；新项目不会自动带上旧画像。

文章、候选稿和反馈是个人数据，默认留在该工作目录。模型读取这些内容时，适用宿主平台的数据政策，本包没有额外网络上传。使用临时沙箱时，需要下载保存状态文件，并在下一会话恢复，无法承诺无感长期保存。不要把状态目录和技能包一起分享。

本仓库只分发宿主版，不包含此前的独立 API 网页原型。

测试方法与实测边界见 [验证记录](VALIDATION.md)，上游依据见 [来源与许可证](THIRD_PARTY_NOTICES.md)。
